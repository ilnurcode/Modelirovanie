# ERP Graph Research v4

Собирать доказательную выборку из графа итеративно. Не принимать поисковый ранг за бизнес-решение и не загружать весь граф в контекст.

## Телеметрия вопроса

Если запрос относится к существующему проекту, первым MCP-вызовом сделать `start_project_query` и сохранить `query_id`. Перед каждым ответом пользователю, включая ошибку или `needs_input`, вызвать `finish_project_query`. Токены передавать в `record_model_call_telemetry` только из точного usage провайдера; токены текущего Codex-хоста не оценивать — MCP сохранит их как недоступные.

## Порядок работы

1. При самостоятельном запуске вызвать `get_model_policy`, затем `start_agent_run`: передать фактические `provider`, `model`, параметры текущего LLM и `skill="erp-graph-research"`. Не угадывать модель. Сохранить возвращённый `provenance`. Если исследование выполняется внутри `$erp-requirements-modeling`, использовать его текущий run/provenance и не заменять активный запуск.
2. Вызвать `graph_status`. Если индекс отсутствует или устарел, завершить run со статусом `failed` и сообщить команду сборки из результата.
3. Разложить смысловой кластер на 2–6 узких поисковых намерений: бизнес-сценарий, объект метаданных, поле/форма, зависимость, знание ИТС, контроль результата. Искать кластер пакетно и повторно использовать найденные узлы.
4. Для каждого намерения вызвать `search_nodes(mode="hybrid")`. Начинать с `strategy=any`, затем уточнять `strategy=all`, `layers` или `node_types`. Каналы FTS5 и semantic — сигналы полноты, а не доказательство.
5. Выбрать небольшое число семян по смыслу. Итоговый rerank означает только близость кандидата.
6. Вызвать `expand_graph` на один шаг с релевантными типами связей. Для пары ИТС↔метаданные в первую очередь проверять `describes_metadata` / `documented_by` и поле `evidence` ребра.
7. Для предполагаемой цепочки вызвать `find_paths`. Отсутствие пути не доказывает отсутствия процесса.
8. Для решающих узлов L4/L3 вызвать `read_source` с узким `query`. Не читать полный исходник без необходимости.
9. Сверить вывод минимум по двум видам свидетельств, когда это возможно: L3 подтверждает объект/поле/связь, L4 — смысл и пользовательский процесс. Автоматическое L3↔L4-ребро подтверждает факт совпадения и его источник, но бизнес-вывод всё равно проверять по содержанию.
10. Если исследование относится к skill/MCP-проекту, сохранить карту через `save_artifact(kind="evidence-map", provenance=<provenance запуска>)`.
11. При самостоятельном запуске вызвать `finish_agent_run`: `completed`, `needs_input` или `failed`. Не оставлять журнал в состоянии `running`.

## Статусы выводов

- `verified_source` — прямо подтверждён первичным исходным фрагментом и точным release;
- `verified_metadata` — подтверждено XML/L3 точного release, но не доказывает автоматически поведение UI или бизнес-смысл;
- `user_decision` — точное решение пользователя;
- `candidate` — релевантный поисковый кандидат, требующий проверки;
- `unresolved` — сведений в текущей выборке недостаточно.

Никогда не преобразовывать `candidate` в verified только из-за высокого ранга или лексической близости. При несовпадении продукта или релиза XML/L3 не может получить verified-статус.

## Контракт результата

Вернуть или сохранить:

```json
{
  "question": "что исследовалось",
  "claims": [{
    "claim": "вывод",
    "status": "verified_source|verified_metadata|user_decision|candidate|unresolved",
    "node_ids": ["точные ID"],
    "relations": ["использованные типы рёбер"],
    "source_snippets": ["краткий пересказ, не длинная цитата"],
    "open_issue": "что ещё проверить"
  }]
}
```

Для карты слоёв, значимых связей и правил обхода читать [graph-contract.md](references/graph-contract.md).

## Ограничения

- Не вызывать Python CLI поиска или проектного препроцесса, если MCP доступен.
- Не строить полный контекст заранее; извлекать следующий фрагмент по результату предыдущего шага.
- Не задавать пользователю вопросы о внутренних пробелах маппинга. Сначала исчерпать поиск и пометить `gap`.
- Не утверждать точное имя поля, команды или регистра без L3-свидетельства.
- Не сохранять артефакт без provenance и не подменять фактическую модель значениями `default`, `unknown` или `host-selected`.
