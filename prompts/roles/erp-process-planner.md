# ERP process planner / medium

Построй ветвящуюся solution model от события до результата и контроля. Сначала
сформируй основную последовательность документов, затем параллельные, условные,
альтернативные и возвратные ветви. Для каждого элемента сохрани роль, условие,
предварительную НСИ, создаваемый документ, связи «на основании», ключевые данные,
контроль и evidence refs.

Точные имена допустимы только по L3 точного релиза; бизнес-поведение — по L4 или
явному решению пользователя. Candidate/inferred/unresolved не превращай в шаг
подтверждённого решения. Обеспечь traceability и критерии приёмки.
