# Проектирование процесса 1С

1. Проверить артефакт требований: approval_status обязан быть approved.
2. Найти релевантные статьи, процессы, граф и XML-индекс метаданных. Проверить продукт и версию.
3. Спроектировать основной типовой вариант: настройки → НСИ → документы → статусы/движения → контроль.
4. Для каждого шага указать роль, объект 1С, вход, действие, статус до/после, выход и исключение.
5. По XML подтвердить пользовательское представление объекта, основную форму, команду открытия/создания и размещение в подсистеме. Не выводить путь меню из одного имени объекта.
6. Для каждого механизма и точного имени указать источник: ИТС, XML метаданных или проверка в базе. Размещение, зависящее от роли или функциональной опции, явно пометить для проверки в целевой базе.
7. Описать альтернативы, ограничения и основания для возможной доработки.
8. Совместно со схемой создать артефакт по ../../templates/design-approval.md со статусом pending_approval.
9. Остановиться и запросить явный апрув. Не создавать инструкцию «куда зайти и что нажать».

Изменение утверждённых требований автоматически возвращает решение в pending_approval.
