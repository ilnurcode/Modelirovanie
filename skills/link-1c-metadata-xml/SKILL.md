# Связь XML метаданных 1С с графом

1. Определить формат выгрузки: Конфигуратор «Выгрузить конфигурацию в файлы» или проект EDT.
2. Зафиксировать имя конфигурации, версию, дату выгрузки и контрольную сумму набора файлов.
3. Не коммитить исходные XML по умолчанию; хранить их в metadata/raw.
4. Извлечь тип, внутреннее имя, UUID, синонимы, подсистемы, реквизиты, табличные части, формы, команды и роли.
5. Создать стабильные узлы вида md-document-supplier-order и связи из references/graph-mapping.md.
6. Связать пользовательские объекты процесса с metadata-узлами отношением implemented_by.
7. Для формы и команды сохранить source_path до XML-файла и статус verified_metadata.
8. Не считать наличие объекта доказательством его видимости пользователю. Для пути интерфейса проверить подсистему, командный интерфейс, роль и форму.
9. При несовпадении ИТС и XML считать XML доказательством конкретной конфигурации, но явно отметить отличие от типовой поставки.
10. После обновления конфигурации перестроить индекс и пометить исчезнувшие узлы deprecated, не переиспользуя их идентификаторы.

## Инструменты

1. Построить полный индекс: `python scripts/index_1c_config.py config --output metadata/index`.
2. Найти объекты по терминам: `python scripts/query_1c_metadata.py <термины>`.
3. Проверить поля и элементы форм: `python scripts/inspect_1c_ui.py <qualified_name> --terms <термины>`.
4. Проверить размещение команды: `python scripts/trace_1c_command.py <qualified_name>`.

Не загружать objects.ndjson целиком в контекст. Сначала выполнять поиск, затем инспектировать только объекты утверждённого процесса.

Перед импортом прочитать references/graph-mapping.md.
