# Конкретная схема процесса 1С

1. Проверить, что требования имеют approval_status: approved.
2. Назначить каждому действию стабильный идентификатор: P01, P02 и далее.
3. Для каждой роли создать отдельный subgraph или дорожку.
4. В узле действия указать идентификатор шага, точное имя объекта 1С и действие пользователя.
5. На переходе указать событие или изменение статуса: Черновик → На согласовании, проведён, создан на основании.
6. В ромбе сформулировать проверяемое условие, а не «всё хорошо?». Подписать все исходы.
7. Показать начальный вход, конечный бизнес-результат, возвраты, отмену, частичное исполнение и значимые исключения.
8. Под схемой дать таблицу трассировки: шаг → роль → объект → статус до/после → вход → выход → источник.
9. Проверить точные имена по ИТС и, если доступно, XML метаданных. Неподтверждённое пометить [проверить в ERP].
10. Поместить схему в пакет design-approval со статусом pending_approval и остановиться.

Схема должна позволять сопоставить каждый узел с будущим разделом инструкции. Не выпускать инструкцию до явного апрува схемы.
