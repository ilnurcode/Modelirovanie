# NewAgent — доказательное моделирование процессов 1С

Основной runtime: **Codex / OpenCode / Pi (только интерфейс) → Python workflow → четырёхслойный hybrid graph search → API-роли проекта**. Нормализацию требований, проектирование и написание инструкции выполняют `erp-translator`, `erp-process-planner` и `instruction-writer` через существующий Wormsoft API-ключ. MCP не требуется.

Ключ задаётся локально и не записывается в репозиторий:

```dotenv
WORMSOFT_API_KEY=ваш_ключ
```

Python ищет ключ в окружении, в `NewAgent/.env`, затем в разрешённых `.env` исходных проектов, не печатая и не копируя секрет. Проверить маршрут без API-вызова: `consultant.cmd --repo . --json runtime-status`. Автоматических повторов нет.

Объединённый сервис на основе lifecycle Кирилла и четырёхслойного графа Яны с атомарными требованиями,
evidence/GAP maps, traceability, acceptance tests, incremental rebuild и полной
телеметрией. См. [быстрый запуск](docs/quickstart.md),
[архитектуру](docs/architecture-unified.md),
[карту интеграции](docs/integration-map.md) и
[происхождение компонентов](docs/provenance.md).

Репозиторий объединяет проверяемую базу знаний по 1С, XML-индекс локальной конфигурации и консольное приложение, которое создаёт проекты консультаций, схемы и пошаговые инструкции.

## Скачать и установить

Готовые сборки находятся в [последнем GitHub Release](https://github.com/ilnurcode/Modelirovanie/releases/latest).
Скачайте setup-архив своей ОС и архитектуры, распакуйте его и откройте launcher:

| Система | Архив | Что открыть |
|---|---|---|
| Windows x64 | `1c-consultant-setup-windows-x64.zip` | `Install 1C-Consultant.cmd` |
| Linux x64 | `1c-consultant-setup-linux-x64.zip` | `Install 1C-Consultant.sh` |
| Linux ARM64 | `1c-consultant-setup-linux-arm64.zip` | `Install 1C-Consultant.sh` |
| macOS Intel | `1c-consultant-setup-macos-x64.zip` | `Install 1C-Consultant.command` |
| macOS Apple Silicon | `1c-consultant-setup-macos-arm64.zip` | `Install 1C-Consultant.command` |

Installer открывает меню. Выберите `Установить или обновить`, затем интернет или
распакованный offline bundle. Приложение 4.1, совместимый граф и нужная платформа
выбираются, скачиваются и проверяются автоматически.

Пока репозиторий приватный, online-установка без GitHub-аутентификации недоступна.
Для внешнего пользователя используйте `1c-consultant-offline-bundle-<версия>.zip`.

После установки:

- Windows: launcher в `%LOCALAPPDATA%\1C-Consultant`, ярлыки на рабочем столе и в меню «Пуск»;
- Linux: `~/.local/share/1c-consultant/1c-consultant`;
- macOS: `~/Applications/1C-Consultant.app`, CLI открывается в Terminal.

Проекты, настройки и активные графы хранятся в постоянном каталоге данных отдельно
от версии приложения, поэтому обновление и rollback их не удаляют.

Подробно: [эксплуатация и обновления](docs/service-operations.md),
[работа с приложением](docs/consultant-cli.md),
[сборка Release](deployment/README.md).

## Основной запуск

```powershell
cd <каталог-репозитория>
consultant.cmd --repo . --json runtime-status
consultant.cmd --repo . --json graph-status
```

Откройте корень NewAgent в Codex или OpenCode: агент вызывает `consultant.cmd`, а собственные токены интерфейса не используются для предметной генерации. Для кнопочного Herdr/Pi запустите `start_erp_pi.cmd` и введите `/erp`. Артефакты сохраняются в `results/<project-id>/agent_artifacts`, ответы — в `answers_md`.

Новое ТЗ можно вставить текстом или загрузить из UTF-8 Markdown: в CLI используйте
`new ... --file "C:\path\tz.md"`, а в Herdr/Pi выберите источник `Загрузить Markdown-файл (.md)`.

## Python CLI в Windows

1. Дважды щёлкните `consultant.cmd` или выполните `./consultant.ps1` в PowerShell.
2. Приложение автоматически использует API-роли и модели из `agent-runtime-policy.json`; Codex/OpenCode остаются интерфейсами.
3. Создайте проект и укажите конфигурацию 1С. Приложение всегда использует полный
   оптимизированный процесс: обязательные вопросы, апрув требований, проект и схема,
   второй апрув, затем инструкция.
4. После результата подтвердите, всё ли устраивает, либо отправьте инструкцию на доработку.

Интерактивный режим использует короткие меню, цветные панели, таблицы, индикаторы этапов и анимацию ожидания. При перенаправлении вывода оформление автоматически отключается; переменная `NO_COLOR=1` отключает цвета вручную.

Если папка открыта непосредственно в Codex/OpenCode, следуйте `AGENTS.md`: все предметные этапы выполняются через Python CLI.

Подробно: [руководство по приложению](docs/consultant-cli.md).

## Структура

| Каталог | Назначение |
|---|---|
| `knowledge/articles/` | очищенные атомарные статьи с источниками |
| `processes/` | типовые бизнес-процессы |
| `graph/` | лёгкий граф сущностей и связей |
| `.agents/skills/`, `skills/` | инструкции интерфейсов и Python workflow |
| `prompts/roles/` | контракты трёх внешних API-ролей |
| `templates/`, `schemas/` | шаблоны и машиночитаемые контракты |
| `results/<project-id>/` | отдельные проекты и их версии |
| `examples/approved/` | индекс только явно подтверждённых инструкций |
| `metadata/index/`, `metadata/slices/` | индекс и компактные срезы XML |
| `1c_modeler_upgrade/` | графы источников, объектов, маршрутов и связей, компактный поисковый индекс и обязательная независимая проверка |
| `source/` | локальная исходная документация, исключённая из Git |
| `local/configurations/` | локальные XML-выгрузки, исключённые из Git |
| `src/consultant_cli/`, `tests/` | приложение и тесты |

## Источники и точность

XML используется только при точном совпадении продукта и релиза. Для иной конфигурации приложение отключает ERP XML, предупреждает консультанта и требует подходящую документацию и разрешённые веб-источники. В подтверждённых шагах инструкции допускаются только `verified` и `verified_metadata`; candidate/inferred/unresolved выносятся в GAP и не становятся пользовательской командой.

В списке проектов отдельно отображаются состояния `В разработке`, `Не подтверждён` и
`Подтверждён`. Удаление переносит проект в `results/.trash/`; использоваться как пример
может только явно подтверждённый проект, прошедший шлюзы проверки.

Крупные source/object-графы Modeler настроены на хранение через Git LFS; компактный
поисковый индекс остаётся обычным файлом репозитория.

Инструкция не становится успешным примером автоматически. После её выдачи консультант должен явно подтвердить результат. Позднее замечание отзывает успешность, исключает инструкцию из реестра примеров и создаёт цикл доработки.

## Разработка и проверка

Требуется Python 3.11 или новее. Приложение не имеет обязательных внешних Python-зависимостей.

```powershell
$env:PYTHONPATH = "src"
py -3 -m unittest discover -s tests -v
py -3 scripts/validate_repository.py
```

Для подготовки локального XML-индекса используйте [руководство по метаданным](metadata/README.md). Перед публикацией любых материалов ИТС проверьте лицензионные права и правила доступа.

Подробнее: [архитектура](docs/architecture.md), [правила контента](docs/content-rules.md), [совместимость агентов](docs/agent-compatibility.md).
