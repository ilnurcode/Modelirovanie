# Контракт входных данных

## Обязательный минимум

1. Описание процесса: шаги, роли, входы/выходы, решения, исключения и границы.
2. Граф объектов: JSON со схемой ниже либо исходные материалы для его построения.
3. Описание конечных объектов: типовой объект ERP/доработка, назначение, реквизиты, владелец, источники данных.
4. Источники: экспорт ИТС и описание пользовательского интерфейса именно для согласованного релиза.

## Рекомендуемая схема графа

```json
{
  "configuration": "1С:ERP 2.5",
  "release": "[указать релиз]",
  "nodes": [{
    "id": "unique-id",
    "label": "Отображаемое имя",
    "type": "Document|Catalog|Register|FunctionalOption|InterfaceRoute|MethodologyArticle|ProcessStep",
    "properties": {"source_path": "…", "source_section": "…", "search_text": "…"}
  }],
  "edges": [{
    "source": "unique-id", "target": "unique-id",
    "relationship": "creates_based_on|writes_to_register|uses_analytics|available_when|located_at|references",
    "source_ref": "файл, раздел"
  }]
}
```

Каждый объект, реквизит, маршрут и связь, используемые в инструкции, должен иметь `source_ref` или источник в `properties`. Неизвестные связи не включайте как подтвержденные.

## Недостаточность входа

При отсутствии одного из обязательных материалов сформируйте первую стадию только в части, подтвержденной источниками, и реестр вопросов. Не выводите маршруты, реквизиты или связи из общих знаний модели.
