# Руководство консультанта

## Запуск

В корне репозитория выполните:

```powershell
./consultant.ps1
```

Или запустите `consultant.cmd`. Без команды откроется меню-мастер. Командный интерфейс доступен через `consultant.cmd --help`.

## Интерфейс меню

Экран очищается при переходе между разделами и показывает текущий путь, карточку проекта и индикатор этапов. Долгие операции сопровождаются анимацией ожидания, а после результатов приложение делает паузу, чтобы сообщение не исчезло.

Цвета автоматически отключаются для перенаправленного вывода и JSON-команд. Для ручного отключения оформления задайте `$env:NO_COLOR = "1"` перед запуском.

## Выбор внешнего интерфейса

В главном меню выберите `4. Выбрать интерфейс` и сохраните один вариант:

- встроенный интерфейс 1C-Consultant;
- Codex Desktop;
- OpenCode;
- Claude Code.

Затем откройте проект и выберите `5. Открыть во внешнем интерфейсе`. Codex запускается
как Desktop-приложение командой `codex app`, остальные интерфейсы — установленными
launcher-командами. Установщик создаёт общий workspace с `AGENTS.md`, командами
`consultant.cmd`/`./consultant` и файлом `config/selected-project.txt`. Поэтому агент
видит выбранный проект и вызывает скомпилированный сервис без установленного Python.

Codex, OpenCode и Claude Code должны быть установлены и авторизованы отдельно;
при отсутствии выбранной программы меню
покажет понятное предупреждение.

## Подключение AI

В главном меню выберите `3. Подключить AI`. AI-подключение — это сохранённый способ связи приложения с AI: установленный Codex/Claude Code/OpenCode или API. Пользователь задаёт ему любое понятное название, например `openai-work`, один раз. При создании проекта ничего вводить в поле AI не нужно: приложение использует основное подключение автоматически.

Локальная проверка не отправляет модельный запрос; удалённая проверка выполняется только по отдельному подтверждению.

Пример подключения установленного Codex:

```powershell
./consultant.cmd agent add codex-local --kind codex_cli --command codex --default
./consultant.cmd agent test codex-local
```

Пример API через переменную окружения:

```powershell
$env:OPENAI_API_KEY = "<ключ>"
./consultant.cmd agent add openai --kind openai_api --model <модель> --secret-env OPENAI_API_KEY --default
```

Ключ не записывается в `consultant.local.toml`. Для профиля `openai_api` по умолчанию используется `https://api.openai.com/v1`; при маршруте, требующем интернета, приложение включает инструмент веб-поиска Responses API. Это может расходовать лимит провайдера.

Если консультант уже открыл workspace в Codex, Claude Code или OpenCode, подключать AI внутрь приложения не нужно. Команда `open-agent` выполняет тот же запуск из CLI:

```powershell
./consultant.cmd open-agent <project-id> --agent codex --launch
```

## Создание проекта

Обычный мастер запрашивает только название проекта, задачу и конфигурацию. Название обязательно. Выбора режима нет: всегда используется полный оптимизированный процесс. Редакция и релиз не спрашиваются и могут остаться пустыми; при необходимости их можно указать позже: `Проект → Изменить → Настройки → Дополнительные`.

Без релиза приложение не использует XML как доказательство точных шагов и запрашивает подходящую документацию/веб-источники. Это безопасное поведение, а не ошибка.

## Полный режим

1. `new` и `run` создают обязательные уточняющие вопросы.
2. `answer --set Q01=...` сохраняет ответы.
3. `approve <id> requirements ...` открывает проектирование.
4. Следующий `run` создаёт проект и схему; `approve <id> design ...` утверждает их.
5. Следующий `run` создаёт инструкцию; отдельный апрув `instruction` делает её успешной.

Обязательный вопрос без ответа блокирует апрув требований. Отключить вопросы нельзя.

```powershell
./consultant.cmd new "Закупка" --prompt "Создай процесс закупки" --product "1С:ERP Управление предприятием 2" --release "2.5.27.49"
./consultant.cmd run <project-id>
```

## Версии и поздние замечания

Успешная инструкция индексируется в `examples/approved/index.ndjson`. Если недостаток обнаружен позже, выполните:

```powershell
./consultant.cmd revoke-approval <project-id> --reason "Обнаружена неточность"
```

Проект получит `needs_revision`, прежняя версия будет исключена из примеров, а после исправления потребуется новый явный апрув.

Команда `revise` является коротким синонимом `request-changes` для запуска того же безопасного цикла доработки.

## Где лежат результаты

Каждый проект хранится отдельно в `results/<project-id>/`: запрос, настройки, вопросы/ответы, проект, схема, инструкция, источники, события, версии и экспорт. После инструкции дополнительно создаются `03-instruction.json`, `03-modeler-review.json` и `03-modeler-review.md`. Приложение ищет кандидатов во всех графах Modeler через `graphs/search-index.ndjson.gz`, сверяет интерфейсные пути и точный локальный XML. В создаваемом JSON нет статуса для сведений без доказательств: такой шаг отклоняется контрактом. `inferred`, неразрешённый путь или незакрытая проверка Modeler блокируют перевод инструкции в `successful`. Команды `status`, `sources`, `validate` и `export` показывают состояние и готовят результат для передачи.

## Статусы и удаление проектов

Список проектов показывает два уровня состояния:

- `В разработке` — проект создаётся, исправляется или находится на промежуточном этапе;
- `Не подтверждён` — инструкция сформирована как черновик или ожидает итоговой оценки;
- `Подтверждён` — инструкция прошла проверки и получила явный апрув.

Точный этап (`ожидаются ответы`, `схема на согласовании`, `нужна доработка` и другие)
показывается в соседней колонке. В примеры попадают только проекты с состоянием
`Подтверждён`, метаданными `approval_status: approved`, `review_status: successful` и
событием явного апрува.

В меню проекта выберите `Ещё` → `Удалить проект` и повторите его ID. Проект исчезнет
из списка и индекса примеров, а папка будет перемещена в восстанавливаемую корзину
`results/.trash/`. Эквивалентная команда:

```powershell
./consultant.cmd delete <project-id> --confirm <project-id>
```
