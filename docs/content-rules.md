# Правила контента

## Нормализация

- сохранять смысл и терминологию 1С;
- удалять навигационный шум, повтор заголовка и служебные элементы выгрузки;
- не объединять разные темы в одну большую статью;
- заголовки делать содержательными, ссылки — относительными внутри репозитория;
- путь по интерфейсу хранить как последовательность точных подписей;
- не «исправлять» название элемента интерфейса без проверки.

## Доказательность

`verification_status` принимает `verified`, `inferred` или `unresolved`. Статья без рабочего источника не может быть `verified`; `unresolved` запрещено использовать в пользовательской инструкции. Для утверждений, зависящих от релиза, указывать `product`, `version` и `accessed_at`.

Если инструкция собрана из нескольких источников, ссылку ставить после соответствующего шага. Если точное название команды не подтверждено, описать ожидаемый результат и пометить шаг как требующий проверки.

## Границы авторского контента

Не публиковать полную закрытую выгрузку ИТС без разрешения. Предпочитать собственные краткие конспекты, метаданные и ссылки на оригинал. Доступ к ИТС не делает материал автоматически разрешённым для распространения.
