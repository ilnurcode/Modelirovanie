# Эксплуатация, обновления и графы 1C-Consultant

## Что входит в систему

Система состоит из двух компонентов:

- Go-installer устанавливает, обновляет и откатывает приложение, управляет графами;
- `1C-Consultant` создаёт консультационные проекты, схемы и инструкции.

Это локальное CLI-приложение, а не фоновый Windows Service, systemd unit или launchd
daemon. После установки оно запускается по требованию пользователя.

## Первый запуск

1. Откройте [последний Release](https://github.com/ilnurcode/Modelirovanie/releases/latest).
2. На Windows/Linux скачайте `1c-consultant-setup-<ОС>-<архитектура>.zip` и
   распакуйте ZIP. На macOS скачайте `.pkg` своей архитектуры и установите его.
3. На Windows/Linux откройте `Install 1C-Consultant.cmd` или `.sh`. На macOS
   запустите `1C-Consultant` из Applications.
4. Дождитесь открытия CLI-меню.
5. В меню выберите `1. Установить или обновить`.
6. Выберите источник пакетов.
7. Подтвердите установку приложения. Нажатие Enter при выборе графов устанавливает
   все доступные графы.

На Linux файловый менеджер может один раз запросить разрешение на запуск `.sh`. На
macOS без Apple notarization может потребоваться `Открыть` в контекстном меню. На
Windows неподписанная сборка может показать SmartScreen.

## Меню installer

| Пункт | Назначение |
|---|---|
| Установить или обновить | Скачать выбранные компоненты и атомарно активировать версии |
| Показать установленные версии | Прочитать локальное состояние без интернета |
| Проверить обновления | Сравнить локальные версии с последним manifest |
| Откатить приложение | Вернуть предыдущую сохранённую версию приложения |
| Управление графами | Показать, скачать, обновить, откатить или удалить граф по номеру |
| Удалить 1C-Consultant | Удалить установку после подтверждения |

Обычному пользователю не нужны параметры терминала или URL manifest. Командный режим
оставлен для администраторов и автоматизации; полный список показывает `--help`.

Installer сохраняется версионно внутри каталога данных и обновляется вместе с
компонентами. Поэтому после первой установки повторно скачивать setup-файл не нужно:
ярлык `1C-Consultant` предлагает запустить сервис или открыть управление установкой.
Технические ID вроде `erp-2.5.27.49` используются только в manifest и командном режиме.

При обновлении графа предыдущая и новая версии сохраняются в состоянии установки.
Пункт `Откатить версию` меняет активную версию без повторного скачивания. Пункт
`Удалить граф со всеми версиями` удаляет весь каталог выбранного графа после
подтверждения; приложение и пользовательские проекты остаются.

## Запуск установленного приложения

Installer создаёт launcher, который передаёт приложению каталог данных и активных
графов:

- Windows: `%LOCALAPPDATA%\1C-Consultant\1C-Consultant.cmd`;
- Linux: `$XDG_DATA_HOME/1c-consultant/1c-consultant` или по умолчанию
  `~/.local/share/1c-consultant/1c-consultant`;
- macOS: `~/Library/Application Support/1C-Consultant/1c-consultant`.

Windows также создаёт ярлыки `1C-Consultant` на рабочем столе и в меню «Пуск».
На macOS PKG устанавливает программу в `/Applications/1C-Consultant.app`; её открытие
запускает CLI в Terminal. Первый запуск открывает installer, последующие — активную
версию сервиса. Данные остаются в `~/Library/Application Support/1C-Consultant`.
Удаление сервиса не удаляет приложение, установленное через PKG.

Работа с проектами, подключение AI, апрувы, экспорт и удаление проектов описаны в
[руководстве консультанта](consultant-cli.md).

Версия 4.2 использует фиксированные Wormsoft API-роли. Ключ задаётся только локально
в `NEWAGENT_API_KEY` или `WORMSOFT_API_KEY`; installer и Release его не содержат.

## Где хранятся данные

В пользовательском каталоге установки находятся:

```text
app/<version>/                         активные и предыдущие версии приложения
graphs/<id>/<configuration>/<version>/ установленные графы
config/installed.json                  активные версии и пути
config/consultant.local.toml           локальные настройки приложения
results/                               проекты, ревизии, ответы и телеметрия
examples/approved/index.ndjson         подтверждённые примеры
.cache/evidence/                       восстанавливаемый поисковый кэш
logs/installer.log                     журнал installer
temp/                                  временные загрузки
1C-Consultant.cmd или 1c-consultant    launcher приложения
```

Приложение получает корень через `CONSULTANT_DATA_DIR`, поэтому проекты и настройки
не лежат внутри `app/<version>` и сохраняются при обновлении или rollback. Путь
активного графа читается из `config/installed.json`. Если состояние отсутствует,
приложение проверяет встроенный граф.

## Как обновляется приложение

Для пользователя:

1. Откройте тот же setup launcher.
2. Выберите `Проверить обновления`.
3. Выберите `Установить или обновить`.
4. Подтвердите приложение и нужные графы.

Installer скачивает только пакет своей ОС и архитектуры, проверяет размер и SHA-256,
распаковывает его во временный каталог, запускает `consultant --version` и только после
успеха меняет активную версию. Предыдущая версия остаётся доступной для отката.

Для разработчика новый выпуск приложения выглядит так:

1. Изменить исходный код и тесты.
2. Увеличить одну и ту же версию в `PACKAGE_MANIFEST.json`, `pyproject.toml` и
   `src/consultant_cli/__init__.py`.
3. Обновить release notes и `FILES.sha256`.
4. Запустить тесты и `scripts/validate_repository.py`.
5. Отправить коммит в GitHub.
6. Запустить workflow `publish release`, передав новую версию, например `0.8.0`.

Workflow нативно собирает application ZIP для Windows x64, Linux x64/ARM64 и macOS
x64/ARM64. Затем `go build` создаёт пять installer-бинарников. Финальный job публикует
manifest, графы, setup ZIP, offline bundle и `SHA256SUMS`. До публикации job должен
получить приватный артефакт `private-graph/erp_graph_mcp.sqlite`; без него сборка
останавливается, чтобы Release не содержал неполный граф.

## Как обновить существующий граф

Текущий пакет содержит граф 1С:ERP. В Graph ZIP входят лёгкие файлы Modeler и только
`graph_rag_data/erp_graph_mcp.sqlite` из четырёхслойного индекса. `chunks.json`,
`chunks_meta.json`, `knowledge_graph.pkl`, `nodes.json`, TF-IDF-файлы и отчёты сборки
в Release не копируются. Для обновления:

1. Пересоберите файлы в `1c_modeler_upgrade/graphs/` штатными скриптами проекта.
2. Проверьте `graph_manifest.json`, route graph, semantic graph,
   `search-index.ndjson.gz` и новый `erp_graph_mcp.sqlite`.
3. Увеличьте `configuration_pack.graph_version` в `PACKAGE_MANIFEST.json`.
4. Если граф требует новую функциональность приложения, увеличьте также
   `application_version` и оставьте в manifest соответствующую минимальную версию.
5. Обновите `FILES.sha256`, прогоните тесты и валидатор.
6. Опубликуйте новый Release.

Локальная сборка получает SQLite явно, не добавляя его в Git:

```powershell
./deployment/scripts/build-release.ps1 `
  -BaseUrl "https://github.com/OWNER/REPO/releases/download/v4.1.0" `
  -ApplicationDirectory application-packages `
  -OutputDirectory release `
  -GraphDatabase "C:\Users\Ilnur\Desktop\graph_rag_data\erp_graph_mcp.sqlite" `
  -GraphDatabaseSha256 "8947dbca6a355792417ca95b91833dcf035bcea5da55fc92b03915a59e812773"
```

Для CI упакуйте SQLite без дополнительного каталога в asset
`erp_graph_mcp.sqlite.zip`, опубликуйте его в отдельном Release
`graph-v<graph_version>`, например `graph-v0.5.0`, и пометьте этот Release как
prerelease, чтобы он не заменял latest Release приложения. Workflow скачивает asset
через `GITHUB_TOKEN` и проверяет SHA-256 из `PACKAGE_MANIFEST.json`; дополнительные
secrets не нужны.

Graph ZIP имеет независимую `graph_version`. Installer скачивает его во новый каталог
и записывает активный путь только после успешной проверки архива.

## Как добавить граф новой конфигурации

Installer уже поддерживает несколько записей в массиве `graphs` файла
`manifest.json`. Каждому пакету требуются:

- постоянный уникальный `id`, например `ut-11.5`;
- понятное `name`;
- `configuration_version`;
- независимая `graph_version`;
- HTTPS `url` архива;
- SHA-256 и размер;
- `minimum_application_version`.

Пример записи:

```json
{
  "id": "ut-11.5",
  "name": "1С:Управление торговлей 11",
  "configuration_version": "11.5.20.95",
  "graph_version": "1.0.0",
  "url": "https://github.com/OWNER/REPO/releases/download/v0.8.0/ut-11.5.20.95-graph-1.0.0.zip",
  "sha256": "<64 hex symbols>",
  "size": 123456,
  "minimum_application_version": "4.1.0"
}
```

Архив должен содержать `graph_manifest.json`, route graph, semantic graph, компактный
поисковый индекс и, для hybrid search, `graph_rag_data/erp_graph_mcp.sqlite`. Путь внутри
архива не должен выходить через `..` и не должен содержать symlink.

Текущий `deployment/scripts/build-release.ps1` автоматически формирует ERP-запись.
Для второй конфигурации нужно добавить в него создание отдельного Graph ZIP и вторую
запись массива `graphs`. Не объединяйте разные конфигурации в один архив: независимые
версии нужны для безопасного обновления и удаления.

Перед одновременной установкой разных продуктов также расширьте выбор графа в
`ModelerReviewService`: сейчас приложение использует последний установленный активный
граф. Оно должно выбирать пакет по продукту и релизу проекта.

## Изменение структуры manifest

Текущая схема имеет `schema_version: 1`. Добавление артефактов в существующие массивы
не требует менять номер схемы. Несовместимое переименование или изменение смысла
полей требует новой `schema_version` и поддержки этой версии в Go-installer до
публикации manifest.

Не редактируйте SHA-256 и размер вручную. Их должен вычислять release workflow из
готовых архивов.

## Offline bundle

Offline bundle нужен для закрытого репозитория и компьютеров без доступа к GitHub.
После распаковки в нём находятся:

```text
manifest.json
application/  application ZIP всех платформ
graphs/       graph ZIP
installer/    raw installer и setup ZIP
```

В меню installer выберите `Скачанный offline bundle` и укажите распакованный каталог.
Проверка SHA-256 выполняется так же, как при online-установке.

## Откат и восстановление

- Пункт `Откатить приложение` меняет активную версию на предыдущую и пересоздаёт
  launcher.
- Ошибка скачивания, SHA-256, распаковки или health check не активирует новый пакет.
- Удаление графа не удаляет приложение.
- Полное удаление разрешается только при наличии `config/installed.json`, что защищает
  от удаления случайного каталога.

## Диагностика

1. Откройте `logs/installer.log`.
2. Проверьте пункт `Показать установленные версии`.
3. Проверьте наличие активных путей из `config/installed.json`.
4. Для online-ошибки учтите: приватный GitHub Release требует аутентификацию, которой
   публичный installer не хранит. Используйте offline bundle либо сделайте репозиторий
   публичным.
5. Сверьте скачанные файлы с `SHA256SUMS` Release.

Секреты AI и подключения к 1С не должны попадать в manifest, graph ZIP,
`installed.json` или release-архивы.
